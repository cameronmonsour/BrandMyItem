## 1. Reservation flow

1.1 **Confirmation state is missing after Stripe returns.** After Checkout completes, the site lands on `#item/{id}` correctly but shows no confirmation. Restore the confirmation modal on that landing: "You're in." · **RESERVATION ID BMI-XXXXXX** (label is "RESERVATION ID", never "SUBMISSION ID") · "Your saved card has not been charged. You'll be charged $X only when this listing fully funds." · buttons **Copy ID**, **Cancel reservation**, **Done**. Trigger it from the Checkout success return (session id in the return URL), not from the dashboard route.

1.2 **Reservations lost on listing rebuild.** Listing `djr99kx` was rebuilt and its reserved spots reset to open, while reservation BMI-73E690 still exists and shows RESERVED on the Track page. Spots and reservations must live in one transaction: a spot is `reserved` if and only if an active reservation references it. Rebuild/reseed operations must either carry reservations forward or delete them. Repair now: re-link BMI-73E690 to Spot 4 on `djr99kx` (or, if the reservation's SetupIntent is gone, mark it cancelled and email the brand).

1.3 **Draft lock survives navigation.** A reservation draft holds the spot for ~10 minutes even when the tab navigates away (which the Stripe redirect always does). Fix both: (a) release the draft on `pagehide`/`beforeunload` via `navigator.sendBeacon` to `DELETE /api/sponsor-reservation-drafts/{id}`, and (b) cut draft TTL to 3 minutes, refreshed every 60 s while the modal is open. A draft that reached Checkout is exempt from (a) and holds until the session expires or completes.

1.4 **Sticky nav paints mid-viewport when the modal opens** (white block above the header). Cause is the body scroll-lock. Lock scroll with `overflow: hidden` on `html` plus `scrollbar-gutter: stable`, or `position: fixed` with the current scroll offset preserved and restored. Verify at 700px, 1440px, 390px: header stays at y=0 with the modal open.

1.5 Production build must not ship Vite's dev error overlay (`server.hmr.overlay`). Confirm `NODE_ENV=production` build has no `vite-error-overlay` element under any error.
