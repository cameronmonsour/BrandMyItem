I'm attaching a single-file HTML web app called BrandMyItem (brandmyitem.com concept) — a marketplace where brands pay to put their logo on someone's everyday item (MacBook, phone, cooler, etc.) in exchange for funding it. Everything is client-side: HTML/CSS/vanilla JS in one file, no build step, no backend, data persisted in localStorage. Product photos are embedded as base64 so there are no external image files.

Set this up as a static site so it runs as-is first — confirm it loads and the core flow works (home page → "Build your item" → pick a catalog item → box editor auto-places ad spots → post it live → "Live items" page → buy a spot → item page shows escrow ledger and owner tools).

Current features already built:

Catalog of 11 real products (MacBook, iPhone, YETI cooler, Stanley tumbler, RIMOWA carry-on, AirPods Max, golf bag, duffel, pickleball paddle, suit, backpack) with an Apple-style variant picker (Finish/color + Storage or Size, with price deltas)
A box editor: rectangle/circle/freeform trace tools to place ad spots on the item photo, auto-partitioning a traced area into N spots
A two-step checkout with a 20% platform fee, an escrow explainer, and a generated Submission ID (BMI-XXXXXX) shown to the buyer
An escrow state machine per spot: held → active → at risk → complete, based on funding % and monthly check-ins
Owner tools: mocked identity verification, and a check-in flow that requires a receipt + purchase date on the first submission (validated against the campaign's funded date) to stop people claiming credit for something they already owned
Auto-generated social share posts (X, Facebook, Instagram-copy) using the real item photo and caption
A "Track my item" page: look up every submission tied to an email address, each with a Bought→Funded→12 monthly check-ins timeline

Important: the "Stripe checkout," "identity verification," and social "connect" buttons are all UI mockups — no real Stripe, no real KYC, no real OAuth. If I ask you to make payments/verification real, that needs an actual backend (Stripe Connect for escrow-style delayed payouts, a real database instead of localStorage, and probably Stripe Identity for KYC) — flag that distinction before writing code so we don't accidentally ship fake payment processing.
